# run-script — the `fvtt.*` reference

Generated by `scripts/measure/run-script-api.mjs` from `src/page/index.ts`; never edited by hand. Every function here is what a tool calls in the page, offered to a `run-script` program as `await fvtt.<name>(args)`. Arguments are the tool’s own shapes, one level deep; a nested type is named, not expanded. Reads pass through on a dry run; writes (create/update/delete/add/remove/set/place/apply/import/configure/…, and `manage*` with a writing `action`) are counted, capped and recorded.

## actors/reads

### `fvtt.exportActorData(args)`

Full-fidelity actor export — the native "Export Data" payload, headless. toObject() is the COMPLETE source document (system, embedded items with their uses/charges and flags, effects, prototypeToken, ownership, folder, _stats) — no sanitizer, no projection: this is the backup/restore path, so nothing may be dropped. The exportSource flag matches ClientDocument#exportToJSON, so the file round-trips through the sheet's Import Data button. Resolves placed-token ids to the token-instance actor (ActorDelta truth), same as the other reads.

args:
- `identifier?: string`

Returns `{ id: any; name: any; type: any; itemCount: any; effectCount: any; data: any; }`

### `fvtt.getCharacterInfo(args)`

Detailed character info for one actor, resolved via the shared fuzzy resolver (exact id, exact name, substring, then PLACED-TOKEN id → that token's ActorDelta-backed actor — the same path searchCharacterItems already had; the ad-hoc game.actors-only lookup here was why manage-actors get / get-entity threw "Character not found" on the token ids their descriptions advertise). Payload mirrors the bridge query: { characterName?, characterId? }. Returns the full CharacterInfo shape the Node character tool consumes: id/name/type, optional img, sanitized system, sanitized items (each with its module `flags` when present — the item-piles NaN forensic read path), effects, and (when present) dnd5e spellcasting.

args:
- `characterName?: string`
- `characterId?: string`

Returns `Record<string, any>`

### `fvtt.updateActorItem(params)`

Edit an embedded Item on an actor by applying a dot-path `patch` (and/or `deletePaths`, and/or a name/img change) via actor.updateEmbeddedDocuments('Item', ...). This is the generic embedded-doc editor: `patch` keys are Foundry dot-paths (e.g. "system.damage.base.number", "system.activities.<id>.attack.bonus") applied as-is — arrays REPLACE whole (dnd5e Sets/arrays are replace-whole). `deletePaths` remove keys via the `-=` form (e.g. to drop an activity by id). params:

Create one or more world actors by copying a specific compendium entry (resolved by exact packId + itemId). Each copy carries the source's full system data, embedded items, effects, and prototype token (with remote token texture URLs cleared), and is filed under the caller's `folder` (id or exact name, created if absent) — default: the auto-managed "Foundry MCP Creatures" Actor folder. Returns { success, totalCreated, totalRequested, actors, tokensPlaced, folder?, errors? }.

- `itemId: string`
- `customNames: string[]`
- `quantity?: number`

### `fvtt.searchCompendium(args)`

Search every (non-Scene) premium compendium pack's index for entries whose NAME matches all whitespace-separated terms in the query. Name-only matching — descriptions/traits are not indexed, and there is no faceted/heuristic filtering (use search-compendium type creatures/spells/ -items for real-system-data facets). Every match is ranked (premium-first, exact-name, then alphabetical); the first `limit` (default 50) come back with the full match count.

args:
- `query: string`
- `packType?: string`
- `limit?: number`

Returns `{ results: CompendiumSearchResult[]; totalFound: number; }`

### `fvtt.warmCompendiumIndexes()`

Index every searchable pack that is not indexed yet, all in flight at once. Idempotent per session: a second call returns the first call's promise. Never throws — a pack that fails to index is skipped (the search skips it too).

Returns `{ packs: number; built: number; ms: number; }`

### `fvtt.listScenes(args?)`

List scenes in the world, optionally filtered by name substring or to active scenes only. Each entry carries what a skill decides on — id, name, active, size, grid, darkness, weather, token/wall counts — and, when `flagScope` is given, that scope's flags (a scene pack's provenance stamp, for dedup). The background path is a get-current-scene / screenshot-scene matter: no skill reads it from a list, and it was 67% of the list's bytes.

args (optional):

- `includeActiveOnly?: boolean`

### `fvtt.prepareSceneShot(args)`

Prepare the page to screenshot a scene: VIEW it, wait for the WebGL canvas to draw THIS scene, fit the whole map into the viewport (unless fit:false → keep the saved camera), and — when mark:true — draw a transient numbered marker over each map-note pin (a QA overlay on the notes layer, the same coordinate space as the pins, so it aligns exactly; NO document changes). Returns scene metadata; the bridge then captures the PNG via page.screenshot. Page-side (game/canvas/PIXI) — proven live by the screenshot spike, not unit-tested by convention.

args:
- `sceneIdentifier: string`
- `fit?: boolean`
- `mark?: boolean`

Returns `{ found: boolean; notFound?: string | undefined; sceneId?: string | undefined; sceneName?: string | undefined; noteCount?: number | undefined; renderer?: string | undefined; dimensions?: { width: number; height: number; sceneX: number; sceneY: number; } | undefined; }`

### `fvtt.pullUsersToScene(args)`

Pull specific users' VIEW to a scene without changing which scene is active — the party-split path (one player off in a side scene while the rest stay put). This is what the cross-scene teleporters do as a side effect of moving a token; here it is the whole operation, so nothing has to move.

args:
- `sceneIdentifier: string`
- `userIdentifiers: string[]`

Returns `{ success: boolean; scene?: { id: string; name: string; } | undefined; pulled: { id: string; name: string; }[]; offline: { id: string; name: string; }[]; selfSkipped: { id: string; name: string; }[]; notFound: string[]; sceneNotFound?: string | undefined; }`

### `fvtt.setLandingScene(args)`
